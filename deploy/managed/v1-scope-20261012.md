## Remaining engineering work

1. Qualify the selected conventional release and original installation bundles
   against the supported public Compose host/database combinations. Preserve
   first publication, private dependency boundaries, persistence, reboot and
   applicable upgrade/rollback checks.
2. Qualify the managed NixOS installation and non-destructive host updates,
   private database/TLS and public ingress boundaries, and the accepted
   stop/start/verify application update path. Keep host, database and application
   maintenance separate.
3. Verify credential publication, use, retirement and applicable restart/failure
   behavior with the exact admitted application. Preserve existing component
   evidence with its original limits.
4. Record artifacts, configurations, checks and limitations in the existing
   [handover record](../adoption.md) and project ledger. Fix observed failures,
   review the resulting changes, pass applicable CI and merge normally.

Off-host backup restore/PITR and independent key retrieval cannot be claimed
under this deferral. Existing disposable backup/restore tests remain useful
component evidence. They do not establish a customer backup service, a provider
loss recovery guarantee or a recovery-time/data-loss SLA.

## Configuration and operational boundaries

Use the explicit [database backup opt-out](README.md#v1-with-off-host-backups-deferred)
for the deferred profile; do not supply placeholder credentials to a running
archiver. The default remains backup-enabled so this decision cannot silently
disable an existing installation's protection.

GitHub secrets are delivered to a protected workflow step or a separately
authorized operator process. Installed services consume private runtime files;
secret values never belong in the flake source, Nix store, public logs or
qualification artifacts. Secret-name metadata alone does not prove a workflow
can authenticate; retain the result of the actual protected operation.

Public Compose, managed NixOS and public-site evidence remain independent.
Reuse the already recorded conventional-site closeout. Replacement Nix-built
application/site/Desktop/CLI adoption remains deferred under the 10 October
reassessment. No third database authority, automatic failover or additional
platform framework is required by this v1 closeout.
