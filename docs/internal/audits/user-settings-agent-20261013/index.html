Personal settings: Profile, Appearance, Security & sessions, API tokens, Archived chats.

SET-01: Personal settings navigation Added

Before: Only Profile, Security and API tokens were exposed.

After: Appearance now has an authenticated page with saved themes and accessible palettes. Existing Archived chats is now discoverable in Personal navigation. Both share the same user-session boundaries.

SET-02: Password command feedback and sign-in Fixed

Before: An incorrect password closed the modal and showed no failure.

After: Pending controls prevent repeated submits. Failed changes retain the dialog and show readable feedback. A confirmed successful change clears passwords and returns to login. The original demo password was restored after the manual interaction.

SET-03: Settings mutation failures Fixed

Before: Rejected display-name saves had no visible explanation; theme failures could leave an unsaved theme displayed.

After: Profile, theme, session and token failures are handled by their owning command component. Profile drafts are retained; failed theme saves roll back. Token create, edit, rotate and delete completed in the local UI. Theme rollback used a labelled controlled 503 response.

CHAT-01: IME composition Fixed

Before: Enter while confirming Japanese input emitted a send event before composition finished.

After: Composing keyboard events preserve the draft and emit zero send events. The before send was intercepted to avoid making a network request. Both screenshots show manual component interactions.

CHAT-02: Inline context editing Fixed

Before: Removing an inline context marker joined Compare and revenue into Comparerevenue.

After: Whitespace and cursor position are preserved: Compare revenue, cursor position 8.

CHAT-03: Disabled chat attachments Fixed

Before: Add files stayed enabled while the chat input was disabled.

After: The file picker, removal controls, drag affordances and attachment handler respect the disabled state. The disabled preview accepted zero files.

CHAT-04: Saved history with an unavailable agent Fixed

Before: Disabling the local agent made an existing conversation appear blank.

After: Owned saved conversations and transcripts remain readable without an enabled model; new turns still require an enabled model. Missing-title work is not queued while disabled.

AGENT-01: Provider change guidance Fixed

Before: Changing provider endpoint without replacing its bound key led to generic failure feedback.

After: The settings UI explains the replacement-key requirement before submission. Nested command ownership prevents unrelated request failures from clearing a pending provider change. Server credential-binding checks remain authoritative.

LOCAL-01: Agent playground configuration Local only

Before: The isolated app was configured for an unavailable audit provider, and its user request could not complete.

After: A deterministic local playground provider is running on the existing private audit interface. The demo conversation completed an authorized sales catalog lookup. This is evidence for local chat and tool transport, not production AI reasoning.
