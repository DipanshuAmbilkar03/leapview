SSO rollout changes removed from the PR. Browser email/password login remains the current flow. The new Microsoft login experience, SSO-only account controls, offline administrator nomination and cutover guide are no longer included. User-interface, agent and dashboard permission fixes remain.

Retained fixes and before / after evidence

The permission screenshots below were captured before the SSO removal using two explicitly labelled local fixture identities. Their original account labels and image contents are unchanged. They record the retained grant, creation and revocation behavior; they do not claim that the removed SSO setup is included or that these scenarios were rerun after removal.

BUILD-01 · Chat offered dashboard creation without a grant

Fixed; grant, permitted creation and revocation demonstrated locally

Before / issue: An Explorer was shown Build a dashboard even though the existing dashboard-create route denied that account. Preview/Add controls could also assume an existing builder was editable before it answered.

After / change: Use the same request-bound project creation permission for chat starters, preview controls and agent authoring tools. Existing dashboard edits wait for an explicit canEdit response from the exact builder frame; failed or cross-origin loads keep editing disabled and show a readable message.

AGENT-02 · Agent authorization and protected metric metadata

Source fixes built; local deterministic chat transport observed; production reasoning and restrictive-policy matrix unverified

Before / issue: Builder turn context could advertise editing for a read-only draft. Legacy restricted credentials with empty permission metadata could enter authoring preparation. Protected semantic members were omitted even when their current consumer could see them.

After / change: Require actual builder edit capability and reject every restricted authoring credential. Resolve protected semantic metadata through the exact principal/model/generation consumer. Expose only permitted member names, labels, types, aggregation and units; redact physical bindings, raw input, expression and filters. Mark definitions as redacted so the model does not infer hidden formulas.

PERM-08 · User permissions stay under administrator control

Manual local permission flow; no user self-grant

Before / issue: The requested experience needs a clear distinction between signing in, reading/exploring, creating dashboards and administering access.

After / change: The local audit administrator grants and removes project roles through the ordinary UI. Explorer can browse governed datasets but cannot create a dashboard. Editor enables dashboard creation while admin pages and self-grants remain denied. Removing Editor removes builder access again.

Ganesh’s reported issues

Original feedback and its before / after evidence are retained below. The original password-ownership guard is separate from the removed SSO login rollout. AGENT-02 adds permission corrections; live AI reasoning remains unverified.

REV-01 · Azure / federated accounts offered local password changes

Fixed; local identity metadata fixture

Before / issue: A retained local credential could expose password controls even when identity management came from the external provider.

After / change: Remove password controls and hints for externally managed identities. Server-side current-user changes and administrator resets require a locally managed identity.

Fixed

After / change: Hide navigation and controls; deny token management pages/streams and forced browser token/session commands. Both manual forced commands returned 403. Typed Current User token/session APIs retain their existing principal-scoped authorization; this policy change covers the browser management portal.

REV-03 · Users had no Data & sharing / Storage page

Fixed

Before / issue: Storage navigation and its page were restricted to platform administrators.

After / change: Add a read-only user Storage page listing authorized Source, Model and Semantic model names/types only. Current credential attenuation and project binding remain enforced. Physical tables, schemas, counts and operational statistics stay administrator-only.

REV-04 · Chat sidebar lacked quick rename

Fixed

Before / issue: The sidebar had Pin, Archive and Delete but no hover Rename or double-click rename.

After / change: Add Rename to hover/focus/touch actions and double-click titles; briefly defer desktop single-click navigation. Focus/select the existing name. Saved name survived reload; original local chat name restored afterwards.

REV-05 · Popularity tooltip spilled over the table

Fixed

Before / issue: Long popularity help was unwrapped and could be clipped by table scrolling.

After / change: Use a bounded top-layer anchored popover with wrapped text, keyboard focus and tap support. Escape/outside pointer dismiss it. Desktop, dark and narrow viewport evidence included.

REV-06 · Agent stopped at dashboard metadata for a metric explanation

Prompt fixed; production reasoning unverified

Before / issue: The supplied recording shows an answer listing dashboard metadata and asking permission to inspect the metric instead of completing necessary authorized reads.

After / change: Strengthen the default system prompt to resolve returned semantic-model references, inspect the definition and dependencies in the same turn, and distinguish permission denial from missing evidence. Avoid unsupported calculation claims and internal metadata boilerplate.

REV-07 · Data Explorer availability depends on permissions

Approved Explorer behavior confirmed; original production user permissions unverified

Before / issue: The supplied feedback reports Explorer unavailable to a user. Viewer and Explorer have different access; missing Explorer permission cannot safely be replaced by self-granting it.

After / change: Earlier PR fixes expose governed semantic datasets to approved Explorers. Current local Explorer shows nine semantic datasets. No silent Viewer upgrade or self-grant path was added.
